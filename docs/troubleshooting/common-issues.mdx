## Common Issues with SideStore

### I have an issue with the latest nightly
#### Cause
Our nightly builds include bleeding-edge features and improvements, some of which may cause instability.
#### Resolution
Switch to the latest stable build. Please do not request support for bugs encountered in nightly builds.

### I am receiving error code: "X"
#### Cause
An error occurred.
#### Resolution
Check our helpful [list of error codes](error-codes)!

### AFC Connection Failure / No Wi-Fi or VPN Connection
#### Cause
Connection issues with the minimuxer service.
#### Resolution
Try refreshing after each step. If they don't work, proceed to the next.
1. If using WireGuard or StosVPN, switch to LocalDevVPN
2. Turn off any DNS-blockers
3. Ensure LocalDevVPN and Wi-Fi are both connected
4. Try again (spamming the button sometimes helps)
5. Restart SideStore
6. Restart LocalDevVPN
7. [Replace your pairing file](/docs/advanced/pairing-file) using iloader.

### SideStore Hangs Partway Through Installation
#### Cause
Cache or protocol issues.
#### Resolution
1. Update SideStore, if applicable. Otherwise, just restart
2. Clear Cache
3. Change Anisette Server
4. In servers- reset adi.pb, then sign out of SideStore and sign back in
5. Restart device
6. Recreate pairing file
7. Reinstall SideStore using iloader

### Unable to Launch SideStore
#### Cause
Multiple possible causes.
#### Resolution
1. Make sure you installed SideStore through iloader
2. Reinstall SideStore

If the above doesn't work, do the following:

1. Delete SideStore and all apps that you have installed from SideStore
2. Reinstall SideStore
3. Import your pairing file and login. (It will give you a prompt to refresh SideStore, select no)
4. Install the `SideStore.ipa` file to your device
5. Import the `SideStore.ipa` file into SideStore like how you would install any other IPA
6. This will allow SideStore to do a clean refresh, and hopefully fix the issue

### No valid pairing file / "The pairing file format is ambiguous"
#### Cause
SideStore fails to properly import the placed pairing file.
#### Resolution
1. Settings->Pairing File Management->Click "Reset Pairing Files", then force close the app.
2. Download and install [idevice_pair](https://github.com/jkcoxson/idevice_pair/#installation).
3. Connect your device to your computer, and select it in idevice_pair.
4. Place the pairing file:
- iOS version \<17.4: choose lockdown -> click load
- iOS version \>=17.4: choose remote pairing -> click create (may ask you to trust the computer)
5. Relaunch SideStore, and it will ask for a pairing file. Click select, and import the file at:
- Standalone SideStore: "On My iPhone/iPad > SideStore > ALTPairingFile.mobiledevicepairing"
- LiveContainer+SideStore: "On My iPhone/iPad > LiveContainer > SideStore > Documents > ALTPairingFile.mobiledevicepairing"
6. Restart SideStore again

### Could not locate signing certificate for "App" / context.targetAppBundle is nil
#### Cause
SideStore is looking for the app bundle in the wrong directory
#### Resolution
**If it's an application installed via an IPA:**
1. Click on the '+' button in the top left
2. Import the IPA of the app, and reinstall it. Do **NOT** delete the app, if you wish to keep all of your data.

**If it's an application installed via a source / if the application is SideStore itself:**
1. Long press the app
2. Click reinstall->from source

### Login Errors (503, -22441, -45063)
#### Cause
Apple changes anisette frequently, which can break SideStore a lot.
#### Resolution
1. Settings -> User Customizations -> On-Device Anisette: OFF
2. Settings -> Anisette Servers -> Select "SideStore (new)"
3. Settings -> Anisette Servers -> Enable Auto Rotation: OFF
4. Settings -> User Customizations -> Anisette Client Config -> Scroll down, click "Remote Server Sync" and then save as overrides
5. Settings -> User Customizations -> Reset adi.pb (keep headers)
6. Sign in like normal

:::note

If these steps don't work, you may want to repeat them, but with a different anisette server. Working alternatives include:

- "SideStore (Windows ADI)"
- "jkcoxson"
- "jkcoxson (Windows ADI)"
- "Lill q"

:::
